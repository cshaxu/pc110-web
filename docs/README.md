# PC110 Web Documentation

This is the single entry point for repository-wide governance and current
architecture. Runtime status is authoritative in `states/CURRENT.md`;
historical records do not override current decisions.

Read in this order:

1. `design/GOAL.md`, `design/ARCHITECTURE.md`, and `design/ROADMAP.md` for the product and staged outcomes.
2. `rules/` for documentation, execution, architecture, and coding constraints.
3. `states/CURRENT.md`, `states/QUEUE.md`, and `states/TODO.md` for current work, candidates, and debt.
4. `proposals/` for unnumbered candidates and `history/` for closed-task requests, evidence, and decisions.
5. `design/REPOSITORY_LAYOUT.md` for the integrated source, runtime, QEMU, and
   public-media boundaries.
6. `etc/SCOPE_EXCEPTIONS.md` for the sole authority on an approved change that
   crosses a default product boundary.
7. `etc/UPSTREAM_INTEGRATION.md` for branch topology, commit classification,
   and the upstream pull-request path.
